## Global Constraints

- 今回は既存Block01–10を実行済み10 runと数える。目標は全体20 run、Block11を含めて残り10 run。これは論理的な作業単位の数え方で、過去のAPI turn・再試行の実測数ではない。
- 観測時点で「NS-P14 Lean化実行スレ」はBlock11を実装中。監査済みの基準はBlock10 commit `791a2c94eda09479d0582f30726669c6d28fbc7b`。Block11の途中成果を完成扱いせず、進行中のcheckoutも変更しない。
- 各runは実装・接続・必要な検証・原稿台帳・監査引継ぎ・通常のPushまでを含む。内部の細分化は可能で、各内部段階でユーザー操作を要求しない。
- 30〜60分という従来の目安は硬い上限にしない。contextの圧縮後も同じ目標を継続し、時間を埋めるための待機はしない。実際の実行制約と未解決事項は正確に報告する。
- 固定toolchain・依存・既存証明と検証原本を保持する。追加の数学公理、`sorryAx`、隠れた未証明入力で接続を済ませない。
- 完全P14は任意体・全数値半群・全Betti行、actual完成接錐とactual interval completion、それぞれの真正な最小表示を対象とする。
- 最終依存は標準基盤`propext`・`Classical.choice`・`Quot.sound`の範囲。公刊入力は形式証明又は証明済みの十分な特殊版で閉じる。
- 数学的な変更は`docs/LEAN_PAPER_ALIGNMENT_JA.md`へ元の式・代替証明・仮定と結論への影響・Lean宣言・原稿反映事項を記録する。

## 依存の管理と見積の更新

[機械可読計画](../../../lean_planning/run_schedule_r02.json)で全50 IDに一つずつ閉鎖担当runを割り当てた。

もしRun13担当の未実装exportが本当に必要なら、その小タスクを前倒しするかO_COORDを未完と表示する。

- Run12後：座標・完備化が実際に閉じたかを確認し、Run13の入力を確定する。
