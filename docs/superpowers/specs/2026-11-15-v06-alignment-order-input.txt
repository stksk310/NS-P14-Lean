## 2 Endpoint は既存の全 j 評価を再利用する

実際の全競合イデアル `competitorFiber`、`actualDeadFiber_eq_inter`、PC／PG 補償、Rhat、全行 consumer を維持してください。競合を有限個の j に置き換えて新しい実核とすることは認めません。gcd(m,u)=1 も仮定しません。

数学的な新経路は次です。j≥1、s≡r+jm (mod u)、r+jm=s+cu、ε_r=[r>0] とすると、

```text
c − ε_r + ε_s = ceil((r+jm)/u) − ceil(r/u) ≥ floor(jm/u) ≥ j.
```

長い側の極小点 (L,K) から作る禁止始点は、符号付き差を計算してから 0 との最大を取り、

```text
A = max(L − jd − c + ε_r − ε_s, 0) ≤ max(Hx − 2j, 0).
```

全 j で第一座標が有界になり、各第一座標で第二座標の最小値を選べば有限生成性が得られます。十分大きい j で第一座標が 0 になり、各競合イデアルに純粋な v 冪も得られます。

現行 Lean には必要な結論が既にあります。`Carry.lean` の `carry_epsilon_lower`、`floor_jm_ge`、`forbiddenStart_height` は全 j の評価です。`CompetitorBounds.competitorMin_finite` は `Antichains.minimal_finite_of_mem` を使い、停止計算を必要としません。新しい ceiling ライブラリや一般二変数有限生成 wrapper の新設は、今回の最小改修には不要です。

次の四箇所を修正してください。

- `NSP14/Endpoint/CompetitorBounds.lean` の `competitorMin_height` は公開型を保ち、`competitorFiber` の全 j witness から直接証明する。長い側点に `exists_minimalFiber_le`、始点に `forbiddenStart_le`、対象の極小性に `Minimal.eq_of_le`、最後に `minimalPoint_height` と `forbiddenStart_height` を使う。Stopping 内の `forbiddenStart_mono` を再利用して依存を戻さない。
- `NSP14/Endpoint/CarrySums.lean` の Stopping import を ActualKernel import へ替え、Volume import は維持する。
- `NSP14/Endpoint/FiniteSocleBounds.lean` の `competitor_zero_column : (0,m+u)∈competitorFiber r` を同じ型で再証明する。`forbiddenStart_tail_zero`／`stoppingStart` の代わりに `forbiddenStart_height` の j=u と `coreHeight≤u−2` を使い、残りは既存の `carry_u`、`minimalFiber_budget` 等でつなぐ。
- `NSP14/Endpoint/FiniteCompetitors.lean` に Stopping の明示 import を追加する。有限計算 API は従来の停止上限を使ってよい。

`CarrySums`／`CompetitorBounds` へ `FiniteMinima`・`SocleInjection`・`FiniteSocleBounds` を import すると循環します。高層の計算モジュールを新証明のために低層へ取り込まないでください。

完了後は `RowPackage`、`SocleBounds`、`Width.Closure` の個別 import 閉包に Stopping が入らないことを検査してください。umbrella の `NSP14` は旧成果も意図的に import するため、この判定の入口には使いません。停止定理の有限計算枝は引き続き動作させてください。

## 3 第一行の整数 slack

新しい純算術補題は、例えば `NSP14/Width/IntegerPayment.lean` に置けます。名前は提案であり、公開 consumer の型を保存すれば整理方法は調整可能です。変数は Nat、算術評価は ℚ に cast して行ってください。

### Antipodal

証明する補題は次です。

```text
h,b : ℕ, 4≤h,
(6:ℚ)*b + 7*h ≤ 11*h^2 + 30
  ⇒ b ≤ Nat.choose (2*h) 2 + 1.
```

A=choose(2h,2)+1、B=(11h²−7h+30)/6 とすると、

```text
A+1−B = (h²+h−18)/6
       = ((h−4)²+9(h−4)+2)/6 > 0.
```

b が整数なので b<A+1 から結論を得ます。h−4 は ℚ 上の差として扱うか、h=4+z として飽和減算を避けてください。

`NSP14/Width/AntipodalComparison.lean` の `actual_antipodal_first` を同じ型でこの補題へつないでください。既存 `antipodal_coreP_bound` による P≤choose(h+1,2)+1、`QCore_first_third`、`actual_core_endpoint_bound`、元の R と R+2h≤W、粗い W≤h² から上の仮定が得られます。

第一行の proof から h=4／h≥5 分岐と `five_wordVolume_eight` への依存を外します。厳密 antipodal presentation・厳密 P／W・Betti 輸送を新経路の前提にしません。独立の既存厳密結果は保存してください。`five_wordVolume_eight` は高次第二行では使うので、リポジトリ全体から削除しません。

### Non antipodal

証明する補題は次です。

```text
u,b : ℕ, 8≤u,
(12:ℚ)*b + 7*u ≤ 5*u^2 + 90
  ⇒ b ≤ Nat.choose u 2 + 1.
```

A=choose(u,2)+1、B=(5u²−7u+90)/12 とすると、

```text
A+1−B = (u²+u−66)/12
       = ((u−8)²+17(u−8)+6)/12 > 0.
```

`NSP14/Width/FiveNonAntipodal.lean` の `actual_five_nonAntipodal_first` を同じ型で置換します。既存 `five_nonAntipodal_volume_remainder : 6*W≤u²+u+6` と `actual_first_volume_fourth` の第一行評価から仮定を導き、u=8,9,10,11／u≥12 の場合分けを外してください。体積上界の既存 mod 3 算術補題を削除する必要はありません。

## 4 資源の第二行支払いから全高次行へ進む

**actual β₂≤target₂ だけでは共通補題の仮定として不十分です。** 同じ資源包絡 B を第二行で支払えることを仮定にしてください。

まず純算術補題を証明してください。e,u は Nat、B は ℚ、e≥2、u≥e とし、

```text
B * choose(e,2)
  ≤ 2*choose(u,3) + u*(e−1) + choose(e−1,3)
```

ならば、2≤i≤e の全てで

```text
B * choose(e,i)
  ≤ i*choose(u,i+1) + u*choose(e−1,i−1) + choose(e−1,i+1).
```

既存 `NSP14.Width.normalized_capacity_monotone` を再利用できます。choose(e,i)>0 は i≤e から確保し、e−i を割らないでください。

さらに e=D.q+2 として、P_C≤B、Rhat+u≤B、上の第二行資源比較から、任意体 k、2≤i≤e で actual β_i≤i*choose(u,i+1) を得る共通 wrapper を作ります。`actual_positive_rows_add` と Pascal の式を使って、同じ B に対する加法形

```text
β_i + u*choose(e−1,i−1) + choose(e−1,i+1) ≤ B*choose(e,i)
```

を経由してください。引算は ℚ 上の通常の引算か、この加法形を用います。B=u²/4 も渡すため B を Nat に限定しません。体 k 上で数値除算しないでください。

配置例は新しい `NSP14/Width/HigherFromSecond.lean`。`Endpoint/PositiveRows.lean` へ `Width/NormalizedCapacity` を import すると、`NormalizedCapacity → SparseSecond → FirstResources → PositiveRows` と循環します。新 wrapper は下層を import し、`SparseHigher`／`FiveHigher` を import しないでください。

- `NSP14/Width/FiveHigher.lean` の `actual_five_higher` の型を保ち、i>5 の source 消滅処理も保存する。i≤5 は新 wrapper へ接続する。u=8 は既存 W≤14 を用いて B=14、第二行の包絡は U₂=104≤112。u≥9 は B=u²/4 とし、z=u−9≥0 に対して第二行の差が `(2*z^3+33*z^2+136*z+33)/6>0` となることを証明する。高次行ごとの `choose_quadratic_step`／`choose_quadratic_from_eight` を呼ばない。これらの一般定理自体は保存する。
- `NSP14/Width/SparseHigher.lean` の `actual_sparse_higher` の型を保ち、既存 `sparse_second_payment` と同じ資源 B=W を新 wrapper へ接続する。既存 `actual_sparse_resource_add` 等の公開定理も保存する。

この共通化は既存資源の使い回しです。最終 comparison や既存の actual 高次結論を wrapper の証明へ呼び戻さないでください。

## 5 Dense を t=2 と t≥3 にまとめる

対象は q≥4、u=q+1+t、2≤t≤q の既存 dense 範囲です。q=3 の別資源は変更しません。

`NSP14/Width/DenseLexResources.lean` で、一つの lex 商から得る同じ K について、既存の core Betti 上界と

```text
t=2 → K≤2,
3≤t → 3*K≤2*t*(t−1)
```

を同時に得る helper を作ってください。既存 `dense_lex_correction_bound` に、t=2 では r=3、t≥3 では r=t を渡せます。後者の `2*t≤choose(t+1,2)` は t=3 から成立します。t=3 専用の補正評価を主経路に残す必要はありません。

既存 `dense_core_lex_bound` の型は保持し、必要なら新 helper から旧条件を導く互換 wrapper にします。旧定理は t=0,1 も量化しているため、新 helper も t≤q の同じ範囲で条件付きの二評価を返し、全体仮定へ t≥2 を追加しないでください。新 helper の statement は、同じ ∃K の中に全行 core 上界と上の二条件を含めてください。別々の lex 商で K を選び直さないでください。

`NSP14/Width/DensePayment.lean` では、次の新しい係数補題が使えます。

```text
q,t,K,c₀ : ℕ,
4≤q, 3≤t, t≤q,
3*K≤2*t*(t−1), 2*c₀=t*(t−1)
  ⇒ q+1+3*t+K ≤ t*(q+1)+c₀.
```

紙上で用いる有理数係数 γ は、次の恒等式で非負です。上の c₀=choose(t,2) とは別の記号です。

```text
γ = (5*t²−17*t−6)/6 + (t−1)*(q−t),
6*γ = 12*(q−4) + 5*(t−3)² + (t−3) + 6*(t−3)*(q−t) ≥ 0.
```

新しい `dense_payment_ge_three` 等は、q≥4、3≤t≤q、j≤q+1、P≤q+1+2t、R≤t、3K≤2t(t−1) から、現行と同じ結論

```text
(j+1)*choose(q+1,j+2) + P*choose(q,j)
  + R*choose(q+1,j) + K*choose(q−1,j)
  ≤ (j+1)*choose(q+t+1,j+2)
```

を証明してください。旧 `dense_payment`／旧 `dense_large_coeff` を呼んで従来の三枝へ戻らないでください。旧定理の型は互換 wrapper 等で保存します。t=2 では従来の R=0、K≤2 の支払いを維持し、既存 `dense_payment` の proof も t=2／t≥3 へ整理できます。

`NSP14/Width/DenseComparison.lean` の actual consumer を、新しい同一 lex 資源と支払いへ接続してください。旧型の h3 条件を経由するだけで新 helper が未使用、という状態で完了としないでください。

境界 q=4,t=3 では γ=0 です。第1行での容量差は 0 になり得るので、必要な不等号は ≤ です。最上位 i=q+2、すなわち j=q+1 も保存し、0 になる二項係数で割らないでください。
